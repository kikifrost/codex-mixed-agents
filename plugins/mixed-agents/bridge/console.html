并发上限设置

并发上限控制同时运行的任务数，与五小时用量额度是两回事。各层同时生效，实际可启动数量受其中最严格的限制约束。0 = 不设置这一层上限；不会关闭用量保护。每组单独保存。

总并发上限

本插件启动的 Kimi 和 GLM 任务合计受此限制，不含原生 GPT。填 0 表示不设置总并发上限；其他层的限制仍有效。降低上限不会取消正在运行的任务。

Z.ai Provider 并发上限

本插件内的 Z.ai 连接共用此上限，只计入通过 Z.ai 调用的 GLM；其他 Provider 的 GLM 不计入。默认 3，可自行调整。填 0 表示不设置这一层上限，任务仍计入总并发。

Kimi 账号并发上限

Kimi 已支持按账号设置并发上限，默认不限制。优先账号不可用、额度不足或并发已满时，考虑下一账号。
账号前缀配置状态当前占用并发上限（0 = 不限制）
填 0 表示不设置该账号的并发上限。相同凭据的别名仍共用账号限制；所有账号继续受总并发、Project 上限和用量保护约束。

全局策略

每个保存按钮独立生效。策略按账号或全局 scope 共享，不是当前连接的独立额度池。

Kimi 用量保护

探测会消耗少量用量；同账号别名共用冷却。探测后仍未知则暂停。

Z.ai 用量保护

建议 10%，留出大于 5% 的缓冲。启用保护后，未知用量暂停该提供商。

优惠时段偏好

其余时段为优惠时段，只在适合度相同时偏好该模型。不会定时启动任务，也不保证实际计费价格。

用量读取与探测

读取用量不运行推理。探测按钮会发送一次固定、无工具的小请求，遵守冷却和并发限制。
